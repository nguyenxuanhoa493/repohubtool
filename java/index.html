Java J2ME on RetroHub

RetroHub runs J2ME games on FreeJ2ME, straight onto the screen — no RetroArch and no libretro core involved. This page covers the parts that are not obvious, starting with the one that confuses everybody: why two games can map their buttons differently.

Install

The emulator is 66 MB and ships inside the app rather than being downloaded, so it works with no network.

  • Installed RetroHub-x-full.zip? You already have it. Open Utilities → Install Java Emulator once and it unpacks.
  • Installed the lite package? Java is not in it. Download the full one and copy it over the folder you have — nothing else is lost.
  • From version 1.43, an emulator older than the one inside the app is upgraded automatically the next time you open RetroHub. Saves are kept.

Where games go

Every J2ME game was written for one specific handset screen, and the emulator has no way to guess which. So the folder a game sits in is what tells it: a jar in Roms/JAVA/240320/ is handed a 240×320 canvas.

The five folders

  • 240320
  • 320240
  • 128128
  • 176208
  • 640360

Only about a quarter of the titles in the library state a size in their filename, so anything unrecognised lands in 240320 — the commonest size. If a game looks cropped or squashed, it is probably in the wrong folder.

To move one: open the game in RetroHub, press the action button and choose Resolution. Doing it in the app rather than by hand matters — it also clears the system menu's game-list cache, which would otherwise keep pointing at the old path.

Phone modes

This is the answer to “why does every game map its keys differently”. J2ME games do not agree on how to read the keypad. Some ask for GameAction (up/down/left/right/fire), some read the raw digits 2/4/6/8, some use codes specific to one manufacturer. The emulator has to translate differently for each, so it carries five phone modes.

ModeWhat it means
PPlain keypad. The D-pad sends the digits 2/4/6/8 and OK sends 5.
NNokia. The D-pad and OK arrive as GameAction — what most games expect.
ESony Ericsson. A handful of titles need this and nothing else works.
SSiemens.
MMotorola.

The mode is remembered per game, in zulu17/bin/config/<game>/game.conf. That is why the game you played yesterday and the one you opened today behave differently — each keeps its own setting. To change it, hold START and tap SELECT until the letter you want appears in the corner; it is saved for that game alone.

If a game's D-pad does nothing while its other buttons work, it is on P. Switch it to N.

Button layouts

H, K and X are three physical pad layouts. Unlike the phone mode these are global — one layout for every game. H is the default and is what the five phone modes P/N/E/S/M all use; picking K or X switches the phone mode to N automatically.

Quitting a game

Press MENU and a confirmation box appears — the game does not close straight away. NO is selected by default so a stray press costs nothing. Left or up picks YES, right or down picks NO, then A or X confirms; B or MENU again cancels. L3 and R3 are no longer quit buttons.

Display

Three presets, switchable in the app or in-game.

  • PIXEL — nearest-neighbour, no colour blending between pixels, whole-number scale factors. The one to try first for anything pixel-art.
  • SMOOTH — linear filtering, fits the largest area that keeps the proportions right. Can look soft on pixel art.
  • HQ — asks SDL2 for its best quality. On this driver that is often identical to SMOOTH, so treat it as experimental.

In the app: Utilities → Java display mode, which writes the whole preset. In game: hold START and press R3, which changes the mode and the integer-scaling flag and leaves the other keys alone. Either way the choice is saved to renderer.conf and used again next time.

Full screen

A 240×320 game is portrait; the Brick Pro panel is 1024×768, landscape. The two proportions are opposites, so no setting both fills the screen and keeps the picture honest. Here is what each choice actually gives you.

ChoicePicture sizeShapeNotes
SMOOTH or HQ576 × 768CorrectScale 2.4×, the largest that fits. Fills the full height, 224 px of border each side.
PIXEL480 × 640CorrectRounds 2.4 down to 2×, so the picture is smaller and there is border on all four sides.
keep_aspect=false1024 × 768Stretched 1.78×Truly fills the panel. Width is magnified 4.27× against 2.4× for height, so everything looks fat.
Rotate the screen1024 × 768CorrectSTART + B. Rotated the game is 320×240 — exactly 4:3, so it lands on the panel at 3.2× with no border at all. You hold the device sideways.
Move to the 320240 folder1024 × 768CorrectThe game is handed a 320×240 landscape canvas, which also fits at 3.2×. Games that adapt to the canvas look best this way; games with a fixed portrait layout break.

The last two rows are the only ways to genuinely fill the panel without distortion, and both ask something of you: one asks you to hold the device sideways, the other only works on games that adapt to the canvas they are given.

Saves

J2ME saves live in Emus/JAVA/zulu17/bin/rms/, one folder per game, and per-game settings in zulu17/bin/config/.

Both sit inside the emulator folder, which is why reinstalling the emulator used to delete them. Since RetroHub 1.42 they are moved aside before the folder is replaced and put back afterwards — including when the install fails halfway.

Troubleshooting

  • The D-pad does nothing but the other buttons workThe game is in the wrong phone mode. It is almost certainly set to P, where the D-pad sends the digits 2/4/6/8 — a game that listens for GameAction hears nothing. Hold START, tap SELECT until N shows in the corner.
  • Two games map their buttons differentlyThat is by design: the phone mode is remembered per game, in zulu17/bin/config/<game>/game.conf. Set each game once and it sticks. To reset one, delete its folder there.
  • The display row in Utilities says OLD and will not openThe emulator on the card is older than the one inside the app — the in-app update carries the app only, not the 66 MB emulator. From 1.43 the app upgrades it by itself the next time you open it. Before that, press Utilities → Install Java Emulator.
  • A game will not start after you moved itThe system menu caches its game list. RetroHub drops that cache whenever it moves a game, so use the app's resolution screen rather than moving the file by hand.
  • Rebuilding the emulator lost my savesOnly on 1.41 and earlier: reinstalling wiped the whole runtime folder, and saves live inside it. Fixed in 1.42 — saves and per-game settings are moved aside and put back.
