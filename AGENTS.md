# AGENTS.md - working rules for this repository

## 1. What this repository is

RetroHub: a retro-gaming front end (ROM store, local library, emulator launcher,
LED/theme/icon tools, OTA updater) **and** the distribution channel that ships it
to TrimUI handhelds.

Two layers, do not mix them up:

| Layer                  | Path                                                                    | Ships to device                     | Rules                                                              |
| ---------------------- | ----------------------------------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------ |
| App payload            | `files/`                                                                | yes, via OTA and the full installer | small, fast, battery-aware; every file hashed into `manifest.json` |
| Release tooling / site | `tools/`, `_src/`, `index.html`, `vi/`, `guide/`, `changelog/`, `java/` | no                                  | build-time only, may use whatever the build machine has            |
| Catalogs and assets    | `catalog/`, `Themes/`, `EmuIcons/`, `emus/`                             | catalogs yes, archives no           | archives live on the GitHub Release tag `assets`, never in git     |

Single source of truth for the version: `files/rh/version.py`. Everything else
(manifest, git tag, website, changelog) is derived from it.

## 2. Target hardware and tech stack

- Devices: TrimUI Brick / Smart Pro (Linux ARM, small screen, ~1 GB class RAM,
  battery powered, slow SD card, Wi-Fi that drops on standby).
- Runtime: Python 3 (the device's own interpreter, or the one bundled under
  `python/` by `launch.sh`). Keep the payload compatible with **Python 3.9+**;
  CI syntax-checks with 3.12.
- Graphics/input: PySDL2 with the pure-python bindings vendored in
  `files/vendor/sdl2`, backed by native SDL2/SDL2_ttf/SDL2_image.
- Third-party runtime libraries are a last resort. `numpy` and `Pillow` are used
  only behind guarded imports inside vendored SDL2; `yt-dlp` only for YouTube.
  Adding a new runtime dependency requires the user's explicit approval.
- Archive extraction uses the bundled `files/bin/7zzs`; HTTP uses `urllib`;
  the ROM store is SQLite.
- Emulator launch is a shell hand-off (`launch.sh`, `/tmp/launch_game.sh`),
  not an in-process emulator.

## 3. Non-negotiable conventions

1. **`PYSDL2_DLL_PATH` search order** stays `$APP/libs:/usr/trimui/lib:/usr/lib64:/usr/lib`.
2. **Manifest integrity**: any change under `files/` changes bytes, so the hash in
   `manifest.json` must be regenerated by the release pipeline - that is how the `.agents/memory` rule about recalculating sha256 when `files/` changes is satisfied, through the pipeline and never by hand. Never hand-edit
   hashes, and never run `tools/make_release.py` on a CRLF checkout: step 3 hashes
   the bytes GitHub actually serves and will refuse (see `docs/`).
3. **Never commit**: `dist/`, `Themes/zips/`, `EmuIcons/zips/`, `emus/*.tar.gz`,
   `catalog/roms_store.sqlite3`, `files/catalog/roms_store.sqlite3*`,
   `files/settings.json` state changes. CI `guard-large-files` fails a tracked
   file over the limit.
4. **i18n**: every user-visible string goes through `tr("key")` with the key
   present in `rh/i18n.py` for both VI and EN. `make_release.py` step 2 reports
   missing keys.
5. **Comments** follow the file they are in: Vietnamese without diacritics is the
   norm in `files/rh`, English in tooling. Explain _why_, not _what_.
6. **Communication with the user is in Vietnamese.**

## 4. Testing: TDD is mandatory

Write the failing check first, then the code, then re-run the check. No fix is
finished without a test or a reproduction that failed before and passes after.

- Keep logic out of SDL2: pure helpers live in leaf modules (`rh/romfiles.py`,
  `rh/storage.py`, `rh/neterrors.py` are the model). Anything that needs a window,
  a font or a controller cannot be tested on a build machine, and untestable code
  is where the bugs in this repo have historically hidden.
- Tests run headless, offline, on the build machine:
    - deterministic file/dir work against a fake SD card: set `SDCARD_PATH` to a
      temp directory, then import `rh.*` and drive the module directly;
    - no network in tests; stub the transport (see the `_fetch_blob` / mirror
      patterns) instead of hitting a real mirror;
    - `python tools/make_release.py` steps 1-5 must pass before a release commit.
- Name test entry points `_src/selftest_*.py` so they never ship inside `files/`.
- Device-only checks (real Wi-Fi, emulator launch, suspend) are manual: run them
  on the handheld over SSH, and never reboot or kill processes on the device
  without the user asking.

## 5. Security: OWASP discipline

- Input from the network, from archives and from catalogs is hostile:
    - verify `sha256` whenever the manifest or catalog provides one;
    - treat ZIP/7z member names as untrusted: strip to `basename` (or verify the
      resolved path stays inside the destination) before writing;
    - validate that catalog paths stay inside the app directory (`_safe_rel`).
- No shell string building: `subprocess` gets an argument list, never
  `shell=True`, and never a filename interpolated into a command line.
- TLS: the payload deliberately uses an unverified SSL context to talk to older
  firmware/mirrors. Do **not** add a new unverified context without a comment
  explaining the device constraint; new endpoints default to verified TLS.
- Secrets: never hardcode tokens; go through `rh/secrets.py` and
  `_src/encrypt_secret.py`. Never print or log a token, cookie or full URL with
  credentials. Keep the SSRF surface small: only fetch catalog/mirror URLs.
- Do not weaken an existing guard (hash check, path check, size cap) to make a
  feature easier.

## 6. Performance, RAM and battery on the device

Optimise for the handheld, not for the build machine.

- **Frame budget**: the render loop runs at ~60 FPS, dropping to a low-power
  sleep when the screen is blanked. Per-frame work must stay O(visible items):
  no directory walks, no network calls, no file reads on the render path.
  Cache with a bound (`MAX_TEXT_CACHE`, `MAX_IMG_CACHE`) and invalidate on
  screen change, never grow an unbounded dict.
- **RAM**: this is a ~1 GB device where a 142 MB emulator load has already been
  killed by the kernel. Stream large files in chunks (catalog, archives) instead
  of `read()` into memory; free SDL textures and staging directories on every
  exit path; cap concurrency (the downloader uses 4 connections on purpose).
- **Battery / network**: one download at a time, retries back off instead of
  spinning, do not poll GitHub or mirrors on a timer, and stop work when the
  device shows no input or the Wi-Fi is offline.
- **SD card**: writes are slow and can fail (FAT/exFAT, read-only DOS flag). Write
  to a staging file and rename into place; unlock files before overwriting; never
  leave a half-written file that later looks like a valid ROM.

## 7. Clean code, no overengineering

- Small, single-purpose functions; prefer the standard library over a helper.
- No speculative abstraction, no configuration knob without a user, no framework
  imported for one call. If a change can be 10 lines, it must not be 100.
- Errors are handled where they can be acted on, with a message the user can
  understand (use the `neterrors` / i18n key pattern). Do not swallow an
  exception silently.
- Keep files and dirs tidy: no dead code, no unused imports, no leftover staging
  directories, no debug prints shipped in a hot path.

## 8. Every change must weigh cost, performance and resources

Before writing code, and again before committing, state (in the commit message or
the PR description) the answers to:

1. **Execution cost** - what extra work happens per frame, per download, per
   launch, and how often? Is it on a hot path?
2. **Performance guarantee** - what is the observable behaviour that must not
   regress (frame rate, download speed, startup time, RAM ceiling, payload size)?
   How was it measured or reproduced?
3. **Resource trade-off** - bytes on the SD card, bytes in the OTA payload, RAM
   peak, network traffic, battery. What was traded away, and why is that the
   right trade on this hardware?

A change that cannot answer these three is not ready.

## 9. Workflow

- **Release rules live in `.agents/memory/release-workflow.md`**; read it before
  any release work. In short: releases go through GitHub Actions on a tag, OTA by
  default, full installer only when explicitly asked, then Telegram notify.
- Typical OTA release: bump `files/rh/version.py`, update `note` (vi+en) in
  `manifest.json`, add the entry to `_src/build_changelog.py`, commit, then
  `git tag vX.YZ && git push origin main --tags`. The payload commit must be on
  the default branch, otherwise the published manifest describes files that are
  not being served.
- Commit messages: `<type>(<scope>): <subject>` (`fix`, `feat`, `perf`, `docs`,
  `release`), Vietnamese or English, in the imperative.
- Desktop smoke test for the payload: `run-desktop.ps1` (windowed by default,
  `-FullScreen`, `-WindowSize WxH`, `-NoLaunch`), see `docs/`.
- After a release: verify a few payload files against the published manifest
  (`raw.githubusercontent` bytes vs `sha256`), and purge the jsDelivr cache for
  `manifest.json` / `rh/version.py`.

## 10. Memory and code discovery

- Follow everything under `.agents/memory/` (`MEMORY.md`, `user-preferences.md`,
  `project-conventions.md`, `release-workflow.md`). If a rule here and a memory
  file disagree, the memory file wins for user preference, this file wins for
  engineering rules, and the conflict must be raised with the user.
- Prefer the codebase-memory-mcp graph tools for finding code
  (`search_graph`, `trace_path`, `get_code_snippet`, `query_graph`,
  `get_architecture`), indexing the repository first if it is not indexed. Fall
  back to `rg` for literals, error strings, configs and non-code files.
- Read `docs/` and the long comments in `files/rh/downloader.py`,
  `files/rh/updater.py`, `files/rh/archive.py`, `files/rh/j2me.py` before
  touching them: they record bugs that were already paid for once.

## 11. Definition of done

- [ ] Reproduction or failing check existed first, and passes now.
- [ ] No new runtime dependency, no new payload file, no payload bloat.
- [ ] User-visible strings through `tr()` with VI+EN keys.
- [ ] Hot paths unchanged or measurably no worse (RAM, frame budget, network).
- [ ] `python tools/make_release.py` steps 1-5 pass (CI or Linux checkout).
- [ ] Version, manifest note and changelog updated for the release commit.
- [ ] Committed-state clean: no build output, no local `settings.json` state, no
      archives, no staging directories.
